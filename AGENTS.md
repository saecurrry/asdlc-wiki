# Instructions for agents using this wiki

## Read before acting

Read README.md, CONTRIBUTING.md, the target project's index and current status. Consult applicable standards and patterns, then retrieve relevant knowledge. Record the document IDs and versions used for material decisions. Do not load every project into context.

## Facts and decisions

Never treat a proposed assumption as an approved fact. Ask short questions when material decisions are missing. Keep project-specific decisions in that project. Preserve original sources and evidence; do not invent approvals, review results, tests or progress.

## Changes and ownership

Use the project template consistently. Keep stable IDs and standard relative Markdown links. Preserve human edits and historical records. A configured orchestrator alone writes authoritative state; workers submit results and reviewers submit findings. Before an orchestrator exists, state files remain templates or drafts, never evidence of execution.

## Learning

Capture findings in project lessons first. Propose shared knowledge with applicability, limitations and evidence. Use independent review before promotion. An agent's claim is not validation. Standards require explicit owner approval; patterns and knowledge require recorded review. Consult CONTRIBUTING.md.

## Review and change impact

Challengers may report zero material findings. Findings require evidence, impact and an actionable resolution. Human approvals bind to exact versions and are distinct from reviewer passes. Material source changes require downstream impact assessment and renewed approval where appropriate.

## Public content

This repository is public. Do not add credentials, personal information, confidential project documents or sensitive operational data.
